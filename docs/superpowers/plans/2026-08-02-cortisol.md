# Gestión de Cortisol — Migración a la Arquitectura Nueva — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Migrate the legacy Gestión de Cortisol module (`cortisol_techniques`, `cortisol_completions`, `cortisol_checkins`, `cortisol_tips`) from `server.js`/`index.html` to the new stack (`apps/api` + `apps/web`), following the exact Routes → Controllers → Services → Models pattern already used for every prior module.

**Architecture:** Three new client/admin-scoped routers in `apps/api`: `cortisolTechniquesRouter` (client-scoped CRUD + video/audio upload, mounted at `/api/clients`), `cortisolLogsRouter` (daily completions + emotional check-ins, mounted at `/api/clients`), `adminCortisolTipsRouter` (global tip bank, admin CRUD + random tip-of-the-day, mounted at `/api`, mirroring `admin-quotes.routes.ts`/`quotes.service.ts` exactly). Frontend: an admin panel embedded in the existing client-detail page (technique CRUD + video/audio upload, mirroring `AdminExercisePanel`), a separate `/admin/cortisol-tips` page (mirroring `/admin/rest-tools`), and a client-facing `/cortisol` page (technique list + mark-complete + daily emotional check-in + tip of the day, mirroring `/training`'s `clientId`-from-JWT pattern).

**Tech Stack:** Same as the rest of the monorepo — TypeScript, Express 4, Drizzle ORM + `postgres` driver, Zod, Next.js App Router, Vitest + Testing Library, multer (video/audio upload).

## Global Constraints

- No design/styling work in this plan — plain functional HTML only, exactly like every other migrated module (a dedicated design pass happens later, across all modules at once).
- Legacy behavior must be preserved exactly: `unlockModule` flips `clients.permissions.cortisol` to `true` and inserts a `client_notifications` row the first time a technique is assigned (`server.js:1590`) — replicate as a local, non-shared helper in `cortisol-techniques.service.ts`, matching the established per-service convention (`exercises.service.ts`, `nutrition.service.ts`, `supplements.service.ts` all have their own private copy).
- `cortisol` is **not** in `LEAD_BLOCKED_MODULES` (`apps/api/src/middleware/require-permission.middleware.ts` already has `['training', 'nutrition', 'supplementation']`, matching legacy `server.js:310` exactly) — do not add `cortisol` to that list, and do not modify that file.
- Client-scoped read routes use `authMiddleware` + `ownerOrAdmin` + `requirePermission('cortisol')`. Admin-only writes (creating/editing/deleting techniques, uploading video/audio) use `authMiddleware` + `adminOnly` only — matching legacy `server.js:1577-1654` exactly. **Do not repeat the mistake caught in the Alimentación task's review**: never drop a `requirePermission` guard to make a test's fixture pass — fix the fixture instead (give the test client `permissions.cortisol = true` before asserting a read-route response).
- `cortisol_completions` and `cortisol_checkins` are both **one-row-per-client-per-day** (`UNIQUE(client_id, completed_date)` / `UNIQUE(client_id, checkin_date)`): `POST .../cortisol-completions` is idempotent (returns the existing row for today if one exists, never creates a duplicate — `server.js:1666-1677`), and `POST .../cortisol-checkin` is an upsert (updates today's row if it exists, else inserts — `server.js:1702-1716`).
- `cortisol_checkins.emotion` is a fixed 6-value enum: `['ansioso', 'irritable', 'cansado', 'abrumado', 'tranquilo', 'energia']` — validate at the Zod layer (matches the legacy inline check at `server.js:1704`) and mirror it as the Postgres `CHECK` in the migration SQL.
- Video upload reuses `uploadFile`/`deleteFile` from `apps/api/src/storage/index.ts` (same helpers `rest-tools.service.ts` and `nutrition.service.ts` already use) — same bucket (`latribu-files`), same multer config pattern (`memoryStorage`, reasonable size limit) already used in `personal-info.routes.ts`/`exercises.routes.ts`.
- **Audio replace/delete must clean up the old file**: `PUT .../cortisol-techniques/:techId` with `audio_url: null` in the body must call `deleteFile` on the technique's existing `audio_url` before clearing it (`server.js:1600-1603`); `DELETE .../cortisol-techniques/:techId` must call `deleteFile` on the technique's `audio_url` after deleting the row (`server.js:1612-1621`); `POST .../upload-audio` replacing an existing audio file must call `deleteFile` on the old URL after the new one is stored (`server.js:1639-1653`). Video (`video_url`) has no equivalent legacy cleanup-on-delete/replace — do not add one that isn't in legacy (YAGNI; note it as a pre-existing legacy gap if a reviewer flags it, don't fix it in this plan).
- `cortisol_tips` is a **global** admin-managed bank (not client-scoped), structurally identical to `mindsetQuotes`/`restTools` already migrated — reuse that exact pattern (`quotes.service.ts`/`quotes.controller.ts`/`admin-quotes.routes.ts` are the closest template, more relevant than `rest-tools.*` since tips have no per-client override, just a flat active/inactive pool + random pick, simpler than quotes' assigned-quote override).
- Tests run against the dedicated test Postgres database via `apps/api/test/helpers/setupTestEnv.ts` (already wired) — never mocks, never production.
- `schema.sql` at the repo root already has these 4 tables (verify no drift against the Drizzle definitions added in Task 2 — same verification step as prior plans' final task).

  title: z.string().min(1),

  duration: z.string().nullable().optional(),
  duration_minutes: z.coerce.number().int().min(0).nullable().optional(),
  duration_seconds: z.coerce.number().int().min(0).nullable().optional(),
  description: z.string().nullable().optional(),
  youtube_url: z.string().url().nullable().optional(),
});
export type CortisolTechniqueInput = z.infer<typeof CortisolTechniqueInputSchema>;

export const CORTISOL_EMOTIONS = ['ansioso', 'irritable', 'cansado', 'abrumado', 'tranquilo', 'energia'] as const;
export const CortisolEmotionSchema = z.enum(CORTISOL_EMOTIONS);
export type CortisolEmotion = z.infer<typeof CortisolEmotionSchema>;

export const CortisolCheckinInputSchema = z.object({
  emotion: CortisolEmotionSchema,
});
export type CortisolCheckinInput = z.infer<typeof CortisolCheckinInputSchema>;

export const CortisolCompletionInputSchema = z.object({

export const CortisolTipInputSchema = z.object({
  content: z.string().min(1),
});
export type CortisolTipInput = z.infer<typeof CortisolTipInputSchema>;

export async function markCompletion(
  clientId: string,
  input: CortisolCompletionInput
): Promise<{ completion: CortisolCompletion; created: boolean }> {
  const date = today();
  const existing = await db
    .select()
    .from(cortisolCompletions)
    .where(and(eq(cortisolCompletions.clientId, clientId), eq(cortisolCompletions.completedDate, date)));
  if (existing[0]) return { completion: existing[0], created: false };

  const [completion] = await db
    .insert(cortisolCompletions)
    .values({ clientId, techniqueId: input.technique_id ?? null, completedDate: date })
    .returning();
  return { completion, created: true };

  const rows = await db
    .select()
    .from(cortisolCheckins)
    .where(and(eq(cortisolCheckins.clientId, clientId), eq(cortisolCheckins.checkinDate, date)));
  return rows[0] ?? null;
}

}

      .returning();
    return updated;
  }

    .insert(cortisolCheckins)
    .values({ clientId, emotion: input.emotion, checkinDate: today() })
    .returning();

  async function handleDelete(tipId: string) {
    try {
      await deleteTip(tipId);
      await refetch();
    } catch (e) {
      setError((e as Error).message);
    }
  }

  if (loading) return <p>Cargando tips...</p>;

  return (
    <div>
      {error && <p role="alert">{error}</p>}

      <label htmlFor="tip-content">Contenido</label>
      <textarea id="tip-content" value={content} onChange={(e) => setContent(e.target.value)} />
      <button type="button" onClick={handleCreate}>
        + Agregar tip
      </button>

      {tips.length === 0 ? (
        <p>Aún no hay tips.</p>
      ) : (
        <ul>
          {tips.map((tip) => (
            <li key={tip.id}>
              {tip.content}
              <button type="button" onClick={() => handleDelete(tip.id)}>
                Eliminar
              </button>
            </li>
          ))}
        </ul>
      )}
    </div>
  );
}

'use client';

import { useEffect, useState } from 'react';
import { listTechniques, markCompletion, getTodayCheckin, postCheckin, getTipOfTheDay, type CortisolTechnique, type CortisolTip, type CortisolCheckin } from '../../lib/cortisol-client';

const EMOTIONS = ['ansioso', 'irritable', 'cansado', 'abrumado', 'tranquilo', 'energia'];

export function ClientCortisolPanel({ clientId }: { clientId: string }) {
  const [techniques, setTechniques] = useState<CortisolTechnique[]>([]);
  const [tip, setTip] = useState<CortisolTip>(null);
  const [checkin, setCheckin] = useState<CortisolCheckin>(null);
  const [emotion, setEmotion] = useState('');
  const [error, setError] = useState<string | null>(null);
  const [loading, setLoading] = useState(true);

  useEffect(() => {
    Promise.all([listTechniques(clientId), getTipOfTheDay(clientId), getTodayCheckin(clientId)])
      .then(([techniqueList, tipOfDay, todayCheckin]) => {
        setTechniques(techniqueList);
        setTip(tipOfDay);
        setCheckin(todayCheckin);
      })
      .catch((e: Error) => setError(e.message))
      .finally(() => setLoading(false));
  }, [clientId]);

  async function handleComplete() {
    try {
      await markCompletion(clientId);
    } catch (e) {
      setError((e as Error).message);
    }
  }

  async function handleCheckin() {
    if (!emotion) return;
    try {
      const saved = await postCheckin(clientId, emotion);
      setCheckin(saved);
    } catch (e) {
      setError((e as Error).message);
    }
  }

  if (loading) return <p>Cargando técnicas de cortisol...</p>;
  if (error) return <p role="alert">{error}</p>;

  return (
    <div>
      {tip && <p>{tip.content}</p>}

      <label htmlFor="cortisol-emotion">¿Cómo te sientes ahora mismo?</label>
      <select id="cortisol-emotion" value={emotion || checkin?.emotion || ''} onChange={(e) => setEmotion(e.target.value)}>
        <option value="">Selecciona</option>
        {EMOTIONS.map((e) => (
          <option key={e} value={e}>
            {e}
          </option>
        ))}
      </select>
      <button type="button" onClick={handleCheckin}>
        Guardar check-in
      </button>

      {techniques.length === 0 ? (
        <p>Todavía no tienes técnicas asignadas.</p>
      ) : (
        <ul>
          {techniques.map((technique) => (
            <li key={technique.id}>
              {technique.title}
              <button type="button" onClick={handleComplete}>
                Marcar como completado hoy
              </button>
            </li>
          ))}
        </ul>
      )}
    </div>
  );
}

'use client';

import { useEffect, useState } from 'react';
import { getSessionToken } from '../../lib/api-client';
import { ClientCortisolPanel } from '../../components/cortisol/ClientCortisolPanel';

function decodeClientIdFromToken(token: string): string | null {
  try {
    const payload = JSON.parse(atob(token.split('.')[1]));
    return typeof payload.id === 'string' ? payload.id : null;
  } catch {
    return null;
  }
}

export default function CortisolPage() {
  const [clientId, setClientId] = useState<string | null>(null);

  useEffect(() => {
    const token = getSessionToken();
    if (token) setClientId(decodeClientIdFromToken(token));
  }, []);

  return (
    <div>
      <h1>Gestión de Cortisol</h1>
      {clientId && <ClientCortisolPanel clientId={clientId} />}
    </div>
  );
}
